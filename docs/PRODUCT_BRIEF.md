# BiliHistory 产品与 UI 设计简报

> 版本：v2.0（C++ 重构版，首发桌面端）  面向：UI 设计师  目标：产出一套完整的高保真原型
> 平台：Windows 桌面优先（C++20 + Qt6 Widgets 原生实现，C++20 协程驱动异步网络层），后续 Linux

---

## 1. 产品定位（一句话）

**BiliHistory —— 把你的 B 站观看历史永久保存在自己电脑里的桌面工具。**

## 2. 解决什么问题（用户痛点）

| 痛点 | 现状 | 我们的解法 |
|---|---|---|
| B 站历史记录会"滚动消失" | 官方历史有条数/时间上限，老记录再也找不回 | 一键抓取全部历史，本地永久留存 |
| "我以前看过的那个视频叫什么来着？" | 官方历史页只能无限下拉，不能搜索 | 本地表格秒级搜索（标题/UP主）、按类型筛选 |
| 数据在云端不属于自己 | 账号出问题=历史全没 | 数据 100% 存本地 CSV，Excel 可直接打开 |
| 担心误操作丢数据 | - | 每次抓取先存时间戳快照备份，总表只增不删 |

**目标用户**：重度 B 站用户（收藏党、考据党、学习党）、数据囤积爱好者、需要回溯"看过什么"的创作者。

## 3. 商业模式（影响 UI 的关键业务）

- **免费试用**：30 天全功能试用（HMAC 防篡改 + 时间防回拨）（浏览/搜索本地数据永久免费）
- **会员**：5 元/月（月付激活码）
- **买断**：38 元永久
- **首发促销**：第一个月购买送永久会员
- **激活方式**：用户付款给客服 → 客服发激活码 → 用户在软件内粘贴激活（离线激活，无账号系统）
- 机器码绑定：用户在激活窗口能看到"本机机器码"，购买绑定版时发给客服

> UI 含义：付费转化路径必须顺滑——试用次数要始终可见；试用耗尽的引导弹窗是最重要的转化页面；激活对话框要让"复制机器码 → 联系客服 → 粘贴激活码"三步傻瓜化。

## 4. 功能清单（已实现，v1.0 范围）

### 4.1 核心功能
1. **一键抓取历史**：后台线程抓取，不卡界面；每页间隔 1.5~3 秒，全量抓取可能持续数分钟（需要清晰的进行中状态）
2. **快照备份 + 总表合并**：每次抓取自动生成 `backups/xxx_时间戳.csv` 快照，再增量去重合并进总表
3. **数据浏览**：表格展示，支持类型筛选（全部/视频/直播/专栏）、关键词搜索（标题/作者）、去重、按时间排序
4. **Cookie 设置**：抓取需要用户提供自己的 B 站 Cookie（设置对话框粘贴保存）
5. **实时日志**：抓取进度与系统消息实时输出

### 4.2 商业化功能
6. **试用计数**：剩余次数展示，抓取成功消耗一次
7. **激活/会员**：授权状态展示（未激活/会员至某日/买断永久）、激活码录入、机器码展示与复制、购买说明

### 4.3 数据字段（表格列）
| 列 | 说明 | 设计备注 |
|---|---|---|
| 标题 | 视频/直播/专栏标题 | 主信息，最宽列 |
| 类型 | 视频 / 直播 / 专栏 | 适合做彩色标签（tag） |
| 作者 | UP主 / 主播 / 作者 | 可点击跳转空间（未来） |
| 观看时间 | yyyy-mm-dd hh:mm:ss | 排序主键 |
| ID | BV号 / 房间号 / 文章ID | 次要信息，可弱化 |
| 完成度 | 观看进度（视频） | 适合做小进度条可视化 |
| 链接 | 跳转 URL | 建议做成"打开"图标按钮，不显示裸链接 |

数据规模：几百 ~ 数万条，需考虑大列表性能与信息密度。

## 5. 页面/界面清单（原型需覆盖）

### P1 主窗口（最高优先级）
当前布局：顶部一排按钮（设置 Cookie / 抓取历史 / 重新加载总表 / 去重 / 按时间排序 / 激活会员）+ 类型下拉 + 搜索框；中间表格；下方记录数与授权状态；进度条；底部日志面板。

**需要的状态**：
- 空状态（首次启动，无任何数据）→ 应引导"设置 Cookie → 开始第一次抓取"
- 正常态（有数据浏览）
- 抓取进行中（按钮禁用、进度反馈"第 N 页 / 已获取 X 条"）
- 抓取完成（结果反馈：新增 X 条 / 总计 Y 条 / 快照已备份）

### P2 首次引导 / Cookie 设置
- 当前是一个简单对话框粘贴 Cookie
- 期望：加"如何获取 Cookie"的图文引导步骤（打开 b 站 → F12 → 复制），降低小白门槛

### P3 激活 / 会员对话框（转化核心页）
包含四块：当前授权状态、本机机器码（+复制按钮）、激活码粘贴框（+立即激活）、购买说明（定价、付款方式、客服联系方式）。
**需要的状态**：未激活（试用剩余 N 次）/ 会员（到期日）/ 买断（永久）/ 激活成功 / 激活失败。

### P4 转化引导弹窗
试用耗尽后点"抓取"触发：告知试用用完 → 展示权益与定价 → 引导进入激活对话框。这是付费转化的关键触点，值得单独设计。

### P5 反馈类弹窗
抓取完成、抓取失败（Cookie 失效是最常见错误，需给出"去设置 Cookie"的直接动作）。

## 6. 关键用户流程（原型需串通）

**流程 A · 首次使用（激活价值）**
启动 → 空状态引导 → 设置 Cookie（图文教程） → 第一次抓取（试用 1/3，进度可视） → 看到自己完整历史（Aha moment：条数、最早一条的时间）

**流程 B · 付费转化**
第 4 次点抓取 → 试用耗尽弹窗（权益+定价） → 激活对话框 → 复制机器码 → （站外付款） → 粘贴激活码 → 激活成功 → 授权状态变绿

**流程 C · 日常使用**
打开 → 点抓取（增量，很快） → 搜索/筛选找回想看的内容 → 点链接跳浏览器观看

## 7. 现有 UI 的问题诊断（设计师重点改进方向）

1. **没有视觉层级**：6 个按钮平铺同权重。"抓取历史"是核心动作应做主 CTA；去重/排序是低频操作可收进菜单
2. **无空状态**：首次打开白屏表格，用户不知道干什么
3. **日志面板喧宾夺主**：占约 1/4 屏，对普通用户是噪音 → 建议默认折叠为一行状态条，可展开
4. **表格是"Excel 感"而非"产品感"**：无类型彩色标签、无完成度可视化、裸 URL 列、密度不可调
5. **抓取进度不透明**：只有不确定态进度条 → 应显示页数/条数实时滚动
6. **商业化触点弱**：授权状态只是右下角一行小字 → 会员应有明确入口与身份感（如买断用户显示徽标）
7. **无品牌感**：无图标、无主题色 → 建议参考 B 站粉（#FB7299）+ 蓝（#00AEEC）做轻量品牌化，支持浅色模式即可（深色可二期）
8. **窗口标题**："B站历史记录管理工具" 可配合产品名 BiliHistory 重新设计

## 8. 设计约束

- 技术栈 C++20 + Qt6 Widgets：QSS 样式、C++20 协程异步网络、PIMPL 隔离 GUI 实现、依赖注入式架构
- 单窗口应用 + 模态对话框结构，暂不做多页面路由；侧边栏导航可以做（左导航 + 内容区是可行的重构方向）
- 中文界面；最小窗口约 900x600，需适配拉伸
- 桌面端无广告；所有支付在站外完成，软件内只做激活码录入

## 9. 交付期望

- 流程 A/B/C 可点击串联
- 一套基础设计规范：色板、字号层级、按钮/标签/弹窗组件样式（方便翻译成 QSS）
